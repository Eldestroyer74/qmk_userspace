# ChieftainDots Roadmap

This roadmap is a backlog, not an approval list. Items start as ideas and must
be discussed, researched, and approved before implementation.

Use **Current Focus** for the next discussion threads. Use **Backlog** as the
long-term memory of ideas, kept decisions, rolled-back experiments, and evidence.

## Lifecycle

- Idea: captured but not prioritized.
- Discussed: intent and ergonomics are understood.
- Researched: QMK compatibility and size risk are understood.
- Approved: ready to implement as the next single feature.
- Implemented: code exists locally.
- Compiled: firmware builds successfully.
- Flashed: firmware has been put on the keyboard.
- Kept: real use confirms the feature should stay.
- Rolled Back: the feature was removed after compile, flash, size, or usability
  concerns.

## Current Focus

Start here if this project has been idle for a while. This short table is the
authoritative resume point; the longer table below is parked detail and history
from earlier discussions.

Current accepted baseline before the local trial: the three-anchor Corne layout
is working physically and should remain the rollback behavior. The latest
documented successful compile is `28280/28672`, leaving `392` bytes free. Both
halves have been flashed with that layout. The current working tree contains the
uncompiled R29 four-anchor trial; the Ctrl/Function swap has not been flashed
and should not be used to explain current physical keyboard behavior.

Kept Function shortcuts: `Function + S` sends Windows screen snip with native
`LSG(KC_S)`, and QMK reported `28280` bytes both before and after that keymap
replacement. `Function + X`, `Function + C`, and `Function + V` send
`Ctrl+X`, `Ctrl+C`, and `Ctrl+V`; physical testing confirmed cut/copy/paste
work. The short-lived Base/Colemak naked-letter clipboard idea was removed
before commit because Trello uses plain `c` to archive hovered cards.

Snap stays in the layout, with caveats. In the accepted flashed baseline the
kept path is deliberate Ctrl+GUI held entry into a Snap surface where `I/J/K/L`
send one-shot `Win+Arrow` shortcuts. In the local R29 trial, Snap moves to
`Function + GUI`. Physical use of the accepted baseline is acceptable for now,
but Snap can still feel unpredictable sometimes; judge the new trial physically
before marking it kept.

Tiny autocorrect is dismissed for now. A two-entry trial for `comming -> coming`
and `i -> I` produced only a 27-byte dictionary table, but the full inherited
autocorrect runtime compiled at `28960/28672`, `288` bytes over. Revisit only
after byte recovery creates enough room or if autocorrect becomes valuable
enough to trade against another visible feature.

M22 byte recovery is a future discussion, not pre-approved implementation. Any
candidate must be negotiated before code changes: decide which areas are in or
out, try one reversible slice at a time, compile before/after, and preserve the
current physical behavior unless a separate feature decision says otherwise.

Static M22 audit recorded: start with requirement negotiation, not deletion.
Best first discussion is whether the Bongocat/OLED role can be simplified with
no visible loss. Tap Dance and RGB may have small cleanup opportunities, but
both are timing/feedback sensitive and should not be broad rewrites. Disabled
autocorrect, combo, archive, docs, comments, and private files are not firmware
byte candidates unless a compile proves otherwise.

Local R29 four-anchor trial is implemented in the working tree and is meant to
be reversible until compiled, flashed, and accepted. Trial order is
`A/; = Control`, `S/L = Symbols`, `D/K = Numbers`, `F/J = Function`;
`Control + GUI = Media`; `Function + GUI = Snap`. Rollback point before the
trial is `1355523 Add left-hand Function Enter and guide updates`. Compile
attempt: first run failed on an unused RGB helper left behind by the routing
change; after removing it, QMK generated a fresh `.hex`/`.elf` but the wrapper
timed out at `check-size` with a broken pipe. Direct HEX parsing measured
`28290/28672`, leaving `382` bytes free. Pause before flashing: the stronger
reason to keep Function as the editing layer is left-hand Enter. Moving editing
onto Control would require new machinery to confirm/paste workflows while the
right hand stays on the mouse, most likely a double-tap-hold Shift or Control
gesture for Enter. That is both likely more expensive and conflicts with the
current principle that double-tap-hold belongs to mnemonic text/snippet output,
not core editing modifiers. Control on `A/;` also makes one-handed `Ctrl+A`
awkward or impossible because `A` is both the modifier seat and the target
letter. Possible refinement if Snap improves enough to keep R29:
double-tap-hold either Control anchor could send `Ctrl+A` for Select All, but
this has the same gesture tension and is especially risky on high-frequency `A`,
where a text-output gesture and a modifier/control gesture would share the same
timing family.

Hardware diagnostic note, 2026-07-01: plugging USB into the right half made the
keyboard behave as if right/left positions were swapped: physical `F` produced
`J`, and double-tapping physical Backspace closed the active window as if the
left-side Tab/Esc/Close tap dance had fired. Because R29 was not flashed, treat
this as a split handedness or stale `EE_HANDS` marker issue on the flashed
three-anchor baseline. Re-flash the right half with the canonical
`dfu-split-right` userspace command before investigating layout code.
